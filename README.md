Высоконагруженный магазин спортивного питания, бадов, пептидов  с использованием DJANGO, POSTGRESQL, HTMX, DOCKER + DOCKER-COMPOSE, REDIS, CELERY LUA, PgBouncer.
План на данный момент)) Использую postgresql для холодных запросов там будут храниться: каталог, пользователи, чеки. В redis - 
все данные которые не требуют постоянного хранения легких корзин hashmap всех анон и юзеров, session_key, uuid4, cache-cataloge разделенный на часто изменяемые и 
не часто изменяемые данные по ключам используя hashmap. UUId4, carts, session_key живут по ttl redis защищен от потери данных персистентность RDB, AOF. 
Для бронирования товаров при оформлении заказа использую атомарную транзакцию lua через eval, evalsha в redis для решения проблемы race conditions и все или не чего 
в случае не оплаты товара так же через lua возвращаем товары в остатки используя tasks для проверки и запуска в фоне. Слияние корзин так же через lua в redis. 
В redis были настроены socket соединения по tcp до 50 шт для решения проблемы открытия закрытия socket теперь всегда открыты.  
Celery для фоновых задач уведомления о статусе заказа и тд. На данный момент настроил инфраструктуру docker + docker-compose django, redis, celery 
находятся в контейнерах а postgresql вне, соединение через тунель.
