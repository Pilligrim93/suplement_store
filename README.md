Проект находится в стадии активной разработки (MVP высоконагруженной E-commerce платформы с открытым исходным кодом)

- Проектирование backend-архитектуры высоконагруженной E-commerce платформы с нуля...

Обязанности:

- Проектирование backend-архитектуры высоконагруженной E-commerce платформы с нуля (стадия MVP).
- Развертывание и конфигурирование гибридной инфраструктуры разработки (контейнеризация Django, PGBouncer, Celery, 4x Redis через Docker Compose с подключением к локальной СУБД PostgreSQL по SSH-туннелю).
- Проектирование схемы реляционной базы данных, профилирование ORM-запросов, устранение N+1 и оптимизация индексов для логарифмического/бинарного поиска.
- Настройка и администрирование PGBouncer для управления пулом постоянных веб-сокетов django-redis и снижения нагрузки на PostgreSQL.
- Разработка распределенной архитектуры NoSQL-слоя: фрагментация и изоляция данных по 4 независимым инстансам Redis (сессии/корзины, кэш верстки, брокер Celery, сухой каталог).
- Написание и оптимизация сложных Lua-скриптов (evalsha) для реализации транзакционных и атомарных операций на уровне Redis (управление остатками, списание, возврат).
- Построение событийно-ориентированной синхронизации данных (Event-Driven) между инстансами Redis с использованием Redis Streams.
- Разработка и интеграция модулей полнотекстового поиска по каталогу товаров на базе RediSearch.
- Реализация механизмов сетевой безопасности и отказоустойчивости: защита от race conditions, внедрение идемпотентности (idempotency keys), настройка стратегий персистентности данных (AOF + RDB).
- Создание бесшовного пользовательского интерфейса (SPA-эффект без перегрузки страниц) за счет интеграции Django с htmx.

Достижения:

- Полностью разгрузил PostgreSQL от горячего трафика, выстроив многоуровневую систему кэширования и очередей, оставив в реляционной БД только мастер-сущности (users, goods, receipts).
- Ликвидировал сетевые издержки на TCP-рукопожатия (handshake) и оптимизировал пул постоянных сокетов django-redis за счет конфигурирования PGBouncer.
- Полностью исключил состояние гонки (race conditions) и обеспечил 100% консистентность данных при оформлении заказов, атомарно связав слияние корзин, списание и возврат остатков через Lua-скрипты (evalsha) в Redis.
- Гарантировал защиту от повторных запросов и дублирования заказов, внедрив механизм идемпотентности на базе idempotency keys.
- Устранил проблему N+1 запросов и оптимизировал индексы в PostgreSQL (настройка B-Tree/BRIN для ускорения бинарного и логарифмического поиска).
- Оптимизировал производительность NoSQL-слоя, фрагментировав данные по 4 изолированным инстансам Redis, и защитил их от потери данных при сбоях с помощью персистентности (AOF + RDB).
- Реализовал отказоустойчивую синхронизацию остатков товаров с каталогом между изолированными инстансами Redis (1-м и 4-м) через шину данных Redis Streams.
- Настроил мгновенный полнотекстовый поиск по сухим данным каталога товаров с помощью модуля RediSearch.
